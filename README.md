# Arbo

目標をサブ目標・タスクのツリーに分解し、子の達成度を集計方法（すべて=min・どれか=max・Σ 合計・k 個以上）に従って親へ伝えるアプリです。
前提（依存関係）の設定、「次の一手」の提示、項目ごとの進捗の記録ができます。
「ガントチャート」ボタンで、タスクの所要日数・前提・担当者から自動で引いた日程表（ガントチャート）に切り替えられます。
ガントチャートでメンバーを登録し、タスクごとに担当者を選べます（ツリーの各タスクや進捗の記録パネルの「担当」からも選べ、どこで変えても連動します）。同じ人のタスクは1つずつ順番に、別の人どうしは並行に進む日程になります。担当が「自動」のタスクは、いちばん早く手が空く人に割り当てます。メンバーが1人（またはいない）ときは、すべて1つずつ順番に進める日程です。
ガントチャートでは「休みの期間」（お盆・年末年始など）を登録でき、その日は所要日数に数えず飛ばして日程を引きます。「土日も休みにする」で週末も同じ扱いにできます。
ツリーの上には、いま着手できるタスクを予定の早い順に並べた「今日やること」が出ます（「表示」で自分の担当だけに絞れます）。

アプリ本体は `my_app/index.html` 1ファイル（HTML・CSS・JavaScript）で完結しています。データはブラウザの localStorage に保存され、Firebase を設定してログインすると Firestore にも保存されます（下記）。
Claude の Artifact として公開した場合は、共有された全員が同じツリーを見て編集でき、ほかの人の変更も自動で反映されます（同時に編集したときは後から保存した内容が残ります）。

## Firebase でデータを管理する・チームで共有する

`my_app/public/firebase-config.js` に Firebase の設定を書くと、画面右上に「ログイン」ボタンが出ます。Google でログインすると、ツリー・メンバー・進捗の記録などすべてのデータが Firestore に保存され、ほかの端末で同じアカウントでログインすれば同じデータを使えます。
設定が空のとき・ログインしていないとき・ファイルを直接開いたときは、これまで通りこの端末（localStorage）にだけ保存します。オフラインでもこの端末には保存され、つながったときにクラウドへ送られます。

### チームで共有する

ログインすると「共有」ボタンが出ます。

- **新しいツリーを作る** … チーム用のツリーを作ります（最初のログインで自分用の「マイツリー」が自動で作られます。これも共有できます）
- **招待** … メンバーのメールアドレス（Google アカウント）を追加します。招待された人はそのアカウントでログインすると「開くツリー」から選べます。「共有リンクをコピー」で送ったリンクからも開けます
- メンバー全員が同じツリーを見られ、有料版のメンバーは編集できます。ほかの人の変更はすぐに反映されます（同時に編集したときは後から保存した内容が残ります）
- メンバーの追加・解除とツリーの削除はオーナー（作った人）だけができます。オーナー以外は「このツリーから抜ける」ことができます
- タスクの担当者の候補は、そのツリーの共有メンバー（招待した人）と同じです。名前は各自の Google アカウントの表示名を使います。共有から外した人の担当は「自動」に戻ります（ログインしていないときは、これまで通りガントチャートで名前を登録します）

### 有料版（共有ツリーの編集）

招待はだれでもできますが、共有中（メンバー2人以上）のツリーを編集できるのは有料版のユーザーだけです。制限は画面だけでなく `firestore.rules` でもかけているので、アプリを改造しても回避できません。

- 有料版かどうかは Firestore の `plans/{uid}` の `until`（期限の日時・タイムスタンプ型）で決まり、今より先なら有効です。`plans` はアプリからは書き込めず、管理者（Firebase コンソール・Admin SDK）や決済の仕組みだけが書き込めます
- 無料: 自分1人のツリーの作成・編集・端末間の同期、招待、共有ツリーの閲覧（抜ける・メンバーの追加や解除もできる）
- 有料版: 共有ツリーの編集。オーナーかどうかは関係なく、編集する人それぞれが有料版である必要があります（無料版のオーナーが招待すると、そのツリーはオーナー自身も閲覧のみになります。メンバーを外せば元に戻ります）
- 期限が切れるとその人は閲覧のみになり、更新すればすぐ編集できるようになります（再読み込みは不要）
- 共有画面のメンバー一覧に、各メンバーが「有料版・編集できます」「無料版・閲覧のみ」「まだ開いていません」（まだ一度もそのツリーを開いていない人）のどれかを表示します
- `firebase-config.js` に `upgradeUrl`（購入ページの URL）を書くと、無料版の人の共有画面に「有料版について」ボタンが出ます

有料版の付け外しは Actions の「Firebase 管理」（「有料版にする」「有料版をやめる」）からできます。手動でやるときは、Firebase コンソールの Firestore で `plans` コレクションにそのユーザーの UID（Authentication の画面で確認）を ID にしたドキュメントを作り、`until` フィールドをタイムスタンプ型で期限の日時にします。
決済と連動させる場合は、Stripe などの Webhook を受けた Cloud Functions（Blaze プランが必要）から Admin SDK で `plans/{uid}.until` を更新します。


データは `trees/{ツリーID}` に1ツリー1ドキュメント（`name`・`owner`・`ownerEmail`・`members`・`json`）で保存され、`members` に入っているメールアドレスの人だけが読み書きできます（`firestore.rules`）。`users/{uid}` には自分用ツリーの ID と最後に開いたツリーを覚えています。

### Firebase なしで試す（テストモード）

URL の最後に `?demo` を付けて開くと、Firebase を使わずに、ログイン・共有・招待・有料版の動きをブラウザの中だけで試せます（公開ページなら `https://<owner>.github.io/todoapp/?demo`、手元なら `npm run dev` で開いた URL に `?demo`）。Firebase の設定は要りません。

- 右上の「ログイン」で好きなメールアドレスを入れるとそのユーザーになります。**別のタブで開くと別のユーザーでログインできる**ので、タブを2つ並べて招待する側・される側を試せます（変更はタブどうしですぐ伝わります）
- 画面上部のバーの「有料版にする／無料版に戻す」で、いまのユーザーの有料版を切り替えられます
- 「テストデータを消す」で最初からやり直せます。テストモードのデータは普段のデータとは別に、このブラウザだけに保存されます（ほかの端末やほかの人とはつながりません）
- 読み書きの可否は `my_app/public/demo-backend.js` で `firestore.rules` と同じ決まりをまねしています。`firestore.rules` を変えたらこちらも合わせて変えてください（本物のルール自体の確認はエミュレーターか本物の Firebase で行います）

### GitHub Pages で使う（設定手順）

公開ページを開発用の Firebase につなぐときは、開発用のプロジェクトを作って、その設定と鍵を下の手順で入れます（本番用とは別のプロジェクトにしておくと、検証で本番のデータを触らずに済みます）。


**Firebase コンソール（https://console.firebase.google.com）で**

1. プロジェクトを作る
2. 「Authentication」→「始める」→「Sign-in method」で **Google** を有効にする
3. 「Firestore Database」→「データベースを作成」（本番環境モードで可。ルールはあとで GitHub Actions から入れます）
4. 「プロジェクトの設定」→「全般」→「マイアプリ」でウェブアプリ（`</>`）を追加し、表示される `const firebaseConfig = { ... };` をコピーしておく
5. 「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵の生成」で鍵（JSON ファイル）をダウンロードする（**この鍵は秘密です。リポジトリにコミットしたり人に渡したりしないでください**）

**GitHub のリポジトリの Settings → Secrets and variables → Actions で**

6. 「Variables」タブに `FIREBASE_CONFIG` を作り、4 でコピーした `const firebaseConfig = { ... };` をそのまま貼る（`{ ... }` の部分だけでも可。`upgradeUrl: "https://..."` を足すと購入ページへのボタンが出ます）
7. 「Secrets」タブに `FIREBASE_SERVICE_ACCOUNT` を作り、5 の JSON ファイルの中身を全部貼る

**GitHub の Actions タブで**

8. 「Firebase 管理」→「Run workflow」で「ルールを反映（firestore.rules）」を実行する（以後 `main` の `firestore.rules` を変えると自動で反映されます）
9. 同じく「GitHub Pages のドメインでログインを許可」を実行する（`<owner>.github.io` を承認済みドメインに追加します。コンソールの Authentication →「設定」→「承認済みドメイン」から手で足しても同じです）
10. 「Deploy to GitHub Pages」を実行する（`main` に push しても動きます）。公開されるページの `firebase-config.js` に 6 の設定が入ります

ローカル（`npm run dev`）で試すときは、`my_app/public/firebase-config.js` に同じ設定を書きます（`localhost` は最初から承認済みです）。

### 招待と有料版の動作を確かめる

1. 公開ページを開き、Google アカウント A でログイン →「共有」→「新しいツリーを作る」
2. アカウント B（別のブラウザやシークレットウィンドウ）でも一度ログインしておく
3. A で B のメールアドレスを招待すると、A も B も無料版なので閲覧のみになる。B の「共有」→「開くツリー」から A のツリーを開ける
4. Actions →「Firebase 管理」→「有料版にする」で A（と B）のメールアドレスと日数を入れて実行すると、再読み込みなしで編集できるようになり、メンバー一覧の表示も「有料版・編集できます」に変わる（「有料版をやめる」で元に戻る）

ログインや読み込みに失敗したときは、画面右上の表示に原因（承認済みドメイン・Google ログインが無効・ルール未反映など）が出ます。詳しくはブラウザの開発者ツールのコンソールを見てください。

### 管理用スクリプト（scripts/admin.mjs）

Actions の「Firebase 管理」から使うスクリプトです。手元で使うときは `GOOGLE_APPLICATION_CREDENTIALS` にサービスアカウントの鍵ファイルのパスを入れて実行します。

```bash
cd scripts && npm ci
GOOGLE_APPLICATION_CREDENTIALS=/path/to/key.json node admin.mjs set-plan someone@example.com 30
```

### 手元で試す（エミュレーター）

本物の Firebase プロジェクトを使わずに試すときは、Java を入れたうえで次を実行し、`firebase-config.js` を `projectId: 'demo-arbo'` と `emulator: {auth: '127.0.0.1:9099', firestore: '127.0.0.1:8080'}` を含む設定にします（ログインはエミュレーターの画面で好きなメールアドレスを入れて行えます）。

```bash
firebase emulators:start --only auth,firestore --project demo-arbo
```

### Firebase Hosting で公開する（任意）

GitHub Pages の代わりに Firebase Hosting でも公開できます（`firebase.json` にビルドと公開先を設定済み）。この場合、承認済みドメインの追加は不要です。

```bash
firebase deploy --only hosting
```

## 起動方法

`my_app/index.html` をブラウザで直接開くだけでも動きます。開発サーバーを使う場合は次の通りです。

```bash
cd my_app
npm install
npm run dev
```

## その他のコマンド

- `npm run build` - プロダクションビルド（`dist/` に出力）
- `npm run preview` - ビルド後のプレビュー

## 公開（GitHub Pages）

`main` に push すると `.github/workflows/deploy.yml` がビルドして GitHub Pages に公開します（Actions タブから手動実行も可）。
初回のみ、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にしてください。

## アプリとしてインストール（PWA）

公開ページはインストールできる Web アプリ（PWA）になっています。Chrome / Edge のアドレスバーのインストールボタン、スマホでは「ホーム画面に追加」から入れられ、一度開けばオフラインでも起動します。

- `my_app/public/manifest.webmanifest` … アプリ名・アイコン・色
- `my_app/public/sw.js` … Service Worker（Firebase SDK もキャッシュしてオフライン起動に対応）。アプリ本体はネット優先（更新はすぐ反映）、つながらないときは保存済みのものを使う。キャッシュの中身を大きく変えたときは `VERSION` を上げる
- `my_app/public/icons/` … アイコン（`icon.svg` / `maskable.svg` が元データ）

## Microsoft Store への公開手順

1. `main` に push して GitHub Pages に公開されたことを確認する
2. https://www.pwabuilder.com に公開 URL を入れて診断し、「Package For Stores」→ Windows でパッケージを作る
3. Partner Center（https://partner.microsoft.com/dashboard）で開発者登録（個人は無料）し、アプリ名を予約する
4. 予約で表示される Package ID・Publisher などを PWABuilder に入れてパッケージを作り直し、`.msixbundle` を Partner Center にアップロードして審査に出す

ストア版の中身は公開ページそのものなので、以後は push するだけで内容が更新されます（アイコンや名前を変えたときだけパッケージを作り直す）。
